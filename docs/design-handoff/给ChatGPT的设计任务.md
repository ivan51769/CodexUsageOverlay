# Codex 用量与更新助手：界面重设计任务

请读取同目录的 interface-gallery.html。这是按 v1.4.23 源码整理的离线 HTML 样例册，包含 7 个主题、3 个位置、3 种胶囊和 2 种排版，共 126 个组合，以及设置、分析、下载器、菜单、通知、引导和对话框样例。网页为结构和视觉说明，不是 WinForms 实机截图；所有数据为虚构样例。

请在保留功能的前提下重新设计界面，并交付可离线运行的单文件 HTML，内嵌 CSS、JavaScript 和 SVG 图标。使用 Microsoft YaHei UI / 微软雅黑。请设计全部主题与交互状态，不要只做一个首页。字体、颜色、边框、尺寸和间距集中为设计变量。用统一组件绘制各个面板。

## 必须保留

- 默认顶部、单行、小圆角和彩字。原生 Codex 主题为浅灰白背景、灰色常规字重、细线无框图标。
- 工具条按钮顺序：刷新、设置、分析、下载。与文字中轴对齐，与宿主按钮同尺寸；有悬浮、按下、焦点、禁用状态。
- 顶部位置向下展开；聊天框内和框下向上展开。设置、分析和嵌入下载面板同宽，分析可用多个 Tab；不要另开分析窗口。
- 主题、位置、排版、胶囊用并列按钮直接选。三个位置独立字号。设置面板底色不透明。
- 文字、数值和预计日期完整显示，不加省略号。双行胶囊按内容收窄，避免两端大片空白。下载操作按钮固定一行且文字完整。
- 公众号和作者名称保持紫色七彩渐变。其余内容遵循当前主题。
- 右键菜单点外部或 Esc 关闭。托盘退出直接退出；托盘打开下载器为独立完整版，Codex 未运行时仍可使用。
- 同时展示加载、无数据、失败、过期、概率预告、下载进度、校验失败和安装结果。
- 给出 Windows 100%、125%、150%、175%、200% 显示缩放与大字体适配方案，不以压缩画布掩盖布局问题。

## 数据边界

本项目是 C# WinForms，不存在已实现的网页 HTTP API。当前额度来自本机 Codex app-server：account/read、account/rateLimits/read、account/usage/read；累计 Token 是全周期值。第三方预告来自 https://www.codexrunway.com/api/status.json 。本地活动分析从 rollout 元数据读取，目前统计去重、子代理区分和指标命名需要修正，不能当成官方分析数字。

请勿编造官方历史分析接口、价格或金额估算。获取不到的数据显示“暂无数据”。65% 会重置是概率预告，不是重置进行中；同时给出预计时间和来源。

## 还需要一起交付的接口约定

请提供“建议实现”的前端与桌面桥接清单，不要声称已存在：

- 读取/刷新账户额度和雷达；返回来源、时间、过期标记和错误。
- 查询今日/7天/30天分析；返回明确指标定义、时间范围、覆盖范围和序列。
- 设置预览、保存、取消；位置、主题、字号等配置的枚举和取值范围。
- 面板打开/关闭和宿主位置变化；不要把屏幕定位交给浏览器猜测。
- MSIX 检查、下载、取消、校验、安装、进度与日志事件；默认下载到桌面。
- 助手自身的 Release 更新入口；与 Codex MSIX 更新分开命名。
- 托盘打开完整版、打开外链和退出动作。

每个建议接口给出参数、返回字段、错误状态、一个虚构 JSON 示例；说明是否只读或有副作用。桌面负责认证、网络请求和安装，HTML 仅负责展示和交互。不要索取或嵌入密钥、Cookie、账户文件或私人对话。

请同时交付：设计说明、统一样式变量、SVG 图标、完整组件/页面清单、状态覆盖表和 DPI 验收清单。避免大屏卡片堆叠导致面板超宽；以紧凑的桌面伴侣工具为目标。

## 补充：分析目标与实际接入能力

用户要求参考 TokenStep 截图的信息组织：总量圆环、Agent 工作强度、今日分时、来源占比、模型消耗。参考其层级和图表，不照搬品牌或把黑金配色覆盖所有主题。嵌入面板仍与设置同宽，将内容分为“概览 / 趋势 / 模型 / 数据来源”Tab，时间范围独立切换“今日 / 7 天 / 30 天”。目标效果见 analytics-target.html。

2026-09-06 核对本机已有协议快照，GetAccountTokenUsageResponse 定义了 dailyUsageBuckets（可为空），其中 startDate、tokens；summary 还定义 lifetimeTokens、currentStreakDays、longestStreakDays、peakDailyTokens、longestRunningTurnSec。当前程序只消费累计 Token。这证明协议定义存在，不证明当前账号会返回所有字段，也不证明覆盖 30 天。先做只读响应验证和日期/时区/缺失天处理，再接入图表。

截图中的原生分析还包括套餐用量按产品/模型、产品活动按模型/使用端、工具活动，并注明近似值、最多延迟 6 小时。当前未确认其完整公开读取接口。插件不会因被安装而自动获得这些数据。接入路径应为：本机合法数据来源 → C# 读取和规范化 → HTML 展示；若采用 WebView2，再实现本地消息桥。此桥接层尚未实现。

建议分析返回值（建议契约，不是官方响应）：period、timezone、source、updatedAt、coverageStart、coverageEnd、isPartial、dailyTokens、hourlyTokens、inputTokens、cachedInputTokens、outputTokens、requestCount、toolCallCount、activeHours、models、products。缺失字段为 null，记录可用性与原因。官方聚合与本地估算分开呈现，不能相加。

缓存命中率仅在分母有效时按 cachedInputTokens/inputTokens 计算；缓存输入通常是输入的一部分，不能再加一次进入总量。账户每日 Token 不能推导按小时、模型和产品的拆分。连续使用天数不等于“达到 1 亿 Token 的天数”。金额暂不展示，除非另行提供可靠价格版本、计费分类和估算标识；订阅套餐用量不能直接换算为 API 实付金额。
