# v1.4.64 内存与首 Token 计时验证

日期：2026-10-22。本文记录 v1.4.64 发布前的本机验证结果。

## 观察与边界

- 安装版 v1.4.63 已连续运行约 38 小时。初次采样：私有工作集约 265 MiB，工作集约 347 MiB，私有提交约 791 MiB。截图中的内存列不等同于进程私有提交。
- 已复现一个确定的高分配路径：`CodexTaskStatusMonitor` 每秒读取日志末尾 2 MiB，文件没有变化也重读。实际会话上的 100 次旧读取产生 852,938,936 字节临时分配、50 次 Gen2 回收。不能据此断言所有常驻内存都来自该路径，也不能凭短期测试排除 UIA/native 长时间运行问题。
- 新状态/上下文读取路径记录偏移；空闲时跳过读取；续写只处理新增字节。文本缓冲最多 32 KiB 头部及 512 字节尾部，保留长消息尾部的完成标记。日志截断、等长改写和头部替换会重新定位。
- 新路径对同一日志 100 次空闲检查共分配 58,424 字节，最后一次读取日志正文为 0 字节，耗时约 2 ms。此处对比的是读取路径的分配，不是整进程内存下降比例。
- 3000 次侧栏 UIA 扫描回归通过，回收后私有内存增长约 4.8 MiB；位图分配失败后隐藏/恢复检查通过。此测试不等同于真实桌面运行 38 小时的验收。

## TTFT 数据口径

- 读取本地 `event_msg / task_complete` 的 `time_to_first_token_ms`；按 `turn_id` 去重，仅计入合法非负整数，缺失、异常及中断记录不计入。
- 官方实现以轮次开始至首次合格模型事件计时，包含推理或工具事件，不等同于最终答案出现时间：[OpenAI turn_timing.rs](https://github.com/openai/codex/blob/2a77e82f09212c9e1bbf02656afca5d8172c5f9e/codex-rs/core/src/turn_timing.rs)。
- 只缓存当前会话的样本 ID、计时数字和读取偏移。首次流式扫描后增量读取；256 KiB 以上的单条计时记录跳过，不假造计时。普通大附件不计入统计。
- 当前会话实测扫描约 516 MB 日志，识别 272 个有效轮次，均值 11.3 s；首次读取约 0.4–0.9 s，保留内存约 50 KB；100 次未变化读取 0 字节正文。
- 信息条显示首 Token 均值；窄空间缩短为 TTFT，仍不足时在悬浮明细查看。样本数始终在悬浮明细显示，不改变输入/缓存/输出口径。

## 验证

- 核心测试：有效/缺失/异常值、零值、重复轮次、跨片段恢复、追加/不完整记录、会话切换、目录边界、截断/重写、大附件有界内存、无新记录时保留上下文、任务完成/中断状态。
- UI 测试：单行/双行、100%–200% DPI、浅深主题、窄布局、悬浮样本数；原有透明文本、定位恢复及嵌入浏览器识别回归通过。
- 不使用强制 GC 或工作集裁剪来制造低内存截图；安装后短期数字不能代替长时间运行验证。
